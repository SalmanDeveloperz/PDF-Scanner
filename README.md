Official product website for **PDF Scanner - Document Scanner**, an Android productivity application offered by Tools & Utilities Apps. The site presents the app's real interface, core scanning workflow, current release details, public review excerpts, and Google Play download destination.

## Product facts represented

- Version 6.3.0
- Updated August 27, 2026
- Android 7.0 and up
- 50,000,000+ downloads
- 4.8 Google Play rating from 476K ratings
- Released September 20, 2020
- Offered by Tools & Utilities Apps
- Company: Darwin Technology L.L.C

See [Plan.md](./Plan.md) for the approved content sources, information architecture, design direction, and project boundaries.

## Technology stack

- **Application:** React 19 and TypeScript
- **Framework:** TanStack Start v1 with TanStack Router
- **Build:** Vite
- **Styling:** Tailwind CSS v4 with semantic design tokens
- **UI primitives:** shadcn/Radix UI
- **Icons:** Lucide React
- **Data fetching foundation:** TanStack Query (available through the application shell)
- **Rendering:** Static prerendered homepage
- **Media:** Managed asset pointers for the supplied product graphics

The current release is intentionally frontend-only. It does not need authentication, a database, or an API because all approved product information is public and static.

## Requirements

- Node.js 20 or newer
- Bun 1.2 or newer (recommended), or npm

## Local setup

```bash
git clone <repository-url>
cd <repository-directory>
bun install
bun run dev
```

The local application is served by Vite at `http://localhost:5173` by default.

## Scripts

```bash
bun run dev       # Start local development
bun run build     # Create the production build and prerender the homepage
bun run build:dev # Build with development settings
bun run lint      # Run ESLint
bun run format    # Format supported files with Prettier
bun run preview   # Preview a local production build
```

## Project structure

```text
src/
├── assets/product/       Managed pointers for authentic product visuals
├── components/ui/        Shared accessible UI primitives
├── content/product.ts    Approved product facts, links, and review excerpts
├── routes/
│   ├── __root.tsx        Document shell, global metadata, and font loading
│   └── index.tsx         Public product homepage and route metadata
├── router.tsx            TanStack Router configuration
└── styles.css            Tailwind setup and semantic design tokens
public/
├── favicon.svg
└── robots.txt
Plan.md                   Product, content, design, and quality plan
vite.config.ts            Static prerender configuration
```

`src/routeTree.gen.ts` is generated by TanStack Router and must not be edited manually.

## Content maintenance

Product values and destinations live in `src/content/product.ts`. Update this module when the verified Google Play listing changes. Keep the following rules:

1. Use the exact public product name.
2. Confirm dates, versions, ratings, install counts, prices, ownership, and Android requirements before changing them.
3. Keep review quotations attributed with the displayed reviewer name and date.
4. Do not add features, platforms, awards, guarantees, or policies without an approved source.
5. Keep the Play Store package URL unchanged unless the product listing itself moves.

## Product media

The seven graphics in `src/assets/product/` are JSON pointers to managed assets rather than copied image binaries. Components import the pointer and render its `url` value.

When replacing a product graphic:

1. Use a current image supplied or approved by the product owner.
2. Upload it through the managed asset workflow.
3. Preserve accurate alternative text and intrinsic width/height.
4. Keep the first visible product image prioritized; lazy-load later images.

## Design system

Global colors and typography are semantic tokens in `src/styles.css`. Page code uses role-based classes such as `bg-background`, `text-foreground`, `bg-primary`, and `text-muted-foreground` rather than literal colors. Manrope is loaded from the document head.

## Accessibility

- Semantic landmarks and heading order
- Descriptive image alternative text
- Keyboard-accessible navigation and controls
- Visible focus behavior inherited from shared UI primitives
- Text and controls designed for sufficient contrast
- Mobile navigation with explicit open/close labels
- No essential information conveyed by animation alone

## Performance

- `/` is statically prerendered through `vite.config.ts`.
- The opening product image is prioritized; media below it is lazy-loaded.
- Uploaded product graphics are served through managed asset URLs.
- No homepage API calls, client data fetching, or database connection are required.
- Client state is limited to the mobile navigation menu.

## Search and sharing

The homepage defines its own title, description, canonical path, Open Graph fields, Twitter card, and `SoftwareApplication` JSON-LD in `src/routes/index.tsx`. The route uses a relative canonical because the project does not yet have a published production domain.

After a production domain is connected, verify the final canonical URL, robots file, social preview, and sitemap before launch.

## Verification checklist

Before release:

1. Run the production build and confirm the homepage is prerendered.
2. Test desktop and mobile widths for overflow, clipping, image failures, and menu behavior.
3. Activate every navigation link and external action.
4. Confirm the browser console and network panel contain no application errors.
5. Recheck all visible product facts against the current Google Play listing.
6. Test keyboard navigation and image alternative text.
