# PDF Scanner tool guide

This guide records the current implementation, its dependencies, user-facing limits, and the cases to verify before release. It is intended for engineering handoff and product discussions; it is not a claim of formal certification or million-user capacity.

## Runtime and processing model

- React 19, TypeScript, TanStack Start/Router, Vite 8, Tailwind CSS 4, Lucide React.
- `pdf-lib` edits, assembles, and saves PDFs in the browser. Dedicated Web Workers are used for image-to-PDF, page operations, PDF marks, and form flattening so those jobs do not block the UI thread.
- PDF.js (`pdfjs-dist`) parses/renders PDFs for OCR and PDF-to-JPG. It uses its own PDF worker; OCR recognition uses Tesseract.js with English language data.
- `qpdf-run` runs qpdf in WebAssembly for password encryption/decryption, structural repair, and optimization. This avoids sending these documents to a conversion server.
- Files stay in the browser for these tools. Browser memory, device capability, browser support, and worker/WASM availability therefore affect the practical maximum. A stated file limit is a guardrail, not a guarantee that every device can process a file at that limit.
- Word, Excel, and PowerPoint to PDF also run entirely in the browser (see "Office to PDF conversion" below). There is no server-side conversion engine, job queue, or object storage in this repository. Do not describe the client-side tools as a globally scalable backend service.

## Office to PDF conversion

Files never leave the device. The shared pipeline lives in `src/lib/office/`:

1. **Validation** (`common.ts`): extension, size, ZIP/OLE magic bytes. OLE files are reported as legacy formats or, when they contain `EncryptedPackage`, as password-protected.
2. **Layout** in an off-screen, same-origin iframe (`host.ts`) so site styles never leak into documents. Office fonts are aliased with `@font-face` (`fonts.ts`): the real font is used through `local()` when installed, otherwise the metric-compatible Carlito (Calibri) and Caladea (Cambria) web fonts keep line breaks close to Office.
   - **Word** (`docx.ts`): the DOCX is pre-processed (PAGE/NUMPAGES fields become markers, headers/footers inherited by later sections, contextual spacing, Symbol/Wingdings bullets mapped to Unicode), rendered with `docx-preview`, then paginated by measuring layout: blocks move to new pages with the section's header/footer; paragraphs split between lines with widow/orphan control; tables split between rows (and inside rows) with repeated header rows. List numbers are frozen into real text, and page numbers are filled in after pagination.
   - **Excel** (`xlsx-model.ts`, `xlsx.ts`): styles, themes/tints, number formats (SSF), merged cells, rich text, hyperlinks, column widths/row heights (with auto-fit), print area, print titles, page setup (paper, orientation, margins, scale, fit-to-page, centering, gridlines, manual breaks, page order), headers/footers (`&P`, `&N`, `&A`, `&F`, `&D`, `&T`), images, charts, and chart sheets. Text overflows into empty neighbour cells and numbers that do not fit show `####`, like Excel. Pages without content are skipped.
   - **PowerPoint** (`pptx.ts`): slides in presentation order, backgrounds (slide → layout → master), shapes/paths, images with crops, tables (including the default table style when a file omits its definition), groups, SmartArt drawings, charts, inherited bullets/auto-numbering, subtitle styles, and linear-light tint/shade colours. Optional speaker-notes pages.
3. **PDF assembly** (`rasterize.ts`, `snapshot.ts`, `vector-text.ts`):
   - Each page is serialized into an SVG `foreignObject` with the frame's CSS (fonts inlined) and drawn to canvas — fast and faithful to the browser's layout. If a browser refuses this, `modern-screenshot` is used as a fallback.
   - Text drawn in Calibri/Carlito, Cambria/Caladea, Arial, Times New Roman or Courier New (or their open equivalents) is written as **real vector text** with the bundled metric-compatible fonts in `src/assets/fonts/office` (SIL OFL), positioned per word at the browser's exact coordinates with measured baselines, clipping, colours and underline/strike-through. That text is hidden from the page image, so it is crisp at any zoom and files stay small.
   - Other fonts, complex scripts (Arabic, Hebrew, Indic, Thai…), rotated or effect-styled text, and text covered by images stay in the page image; an invisible text layer keeps them searchable/selectable (Helvetica for Latin, DejaVu Sans for other scripts).
   - External links become clickable PDF link annotations.
   - The **Print** button sends the laid-out pages (with per-page `@page` sizes) to the browser's print dialog, which produces a fully vector PDF with the device's real fonts.

### Known limitations

- Pagination is recomputed in the browser. With the same fonts it closely follows Word, but a page can break a few lines differently (for example when the device lacks the document's fonts). Floating objects anchored to page positions, text boxes, footnotes placement per page, and multi-column sections are approximated.
- Excel: formulas are not recalculated (cached values are shown; a warning appears when values are missing); conditional formatting, sparklines, pivot styling, shapes/text boxes in drawings, and exotic chart types are not rendered.
- PowerPoint: animations, transitions, audio and video are omitted; some effects (3D, glow, soft edges, WordArt transforms) and uncommon custom geometry are approximated.
- Legacy binary formats (`.doc`, `.xls`, `.xlsb`, `.ppt`) and password-protected files are rejected with a clear message.

## Test and release checklist

The codebase does not currently define a formal automated test script. Use this list for manual QA or turn the cases into an automated browser/worker suite. A successful TypeScript/build/lint check is not a substitute for exercising real document fixtures.

### Shared PDF cases

- Valid single- and multi-page PDFs; portrait/landscape, mixed page sizes, rotation, image-heavy pages, annotations/forms, and non-Latin content.
- Empty file, non-PDF renamed `.pdf`, truncated/corrupt xref/trailer, unsupported objects, encrypted file, and wrong password where applicable.
- Exact maximum and one-over input/output/page limits; 0-byte input; large but valid file; timeout/cancel; low-memory behavior; worker or WASM load failure; repeated runs and route unmount during processing.
- Verify the downloaded file opens in at least two independent PDF readers and visually compare representative pages. Check console for unhandled errors and ensure temporary object URLs/workers are released.

### Tool-specific cases

- Merge: 2 and 20 files, selected order, duplicate source, mixed rotations/page sizes, aggregate byte/page boundary.
- Split/extract/remove: single page, first/last page, disjoint and overlapping ranges, malformed range, out-of-range page, remove-all rejection, 20/21 ranges.
- Organize: reverse/repeated ordering attempts, rotate each direction, remove pages, preserve intended rotation in saved PDF.
- Compress/repair/archive: image optimization off/on, already-small input, warnings, malformed source, output larger than source, repairable and irrecoverable corruption. Confirm archive copy is not presented as certified PDF/A.
- OCR: clear scanned English, skew/low contrast, blank page, mixed text/image, maximum 30 pages, unsupported language expectations, offline/missing model failure; verify both text selection/search and rendered appearance.
- Flatten: form with filled and blank fields, checkbox/radio, no-fields rejection, verify flattened appearance and remaining annotations.
- Image to PDF: JPEG, transparent PNG, browser-supported WebP/AVIF, EXIF-oriented photo, corrupt and zero-byte file, GIF first frame, 100/101 files, pixel/dimension/input/output limits, ordering and all paper/margin options.
- PDF to JPG: rotated/mixed-size pages, transparent PDF graphics rendered onto white, quality slider values, single and 100-page file, per-page pixel and aggregate-pixel limits, output-size limit, password/corruption, cancel/timeout, and verify each download is a valid JPEG with expected page dimensions.
- Scan documents: front/rear/no camera, denied permission, stopped stream, rapid capture, photo import, page reorder/remove, 100/101 images, EXIF orientations, image decoder and pixel limits, worker cancellation/timeout, and open the saved PDF to verify page order and framing.
- Photo to searchable PDF: 1/30/31 photos, image order, camera/EXIF rotations, unsupported/corrupt images, generated PDF at/over OCR size limit, OCR model/network failure, cancel during assembly/OCR, and verify searchable layer visually aligns with each page.
- Smart page cleanup: all rotation angles, mixed image orientation, each enhancement, transparent PNG, unsupported browser canvas filters, boundary image dimensions/aggregate pixels, and inspect output for clipping or unreadable contrast.
- Receipt extractor: image and PDF paths, no text, skew/blur, multiple currencies/date formats, totals/subtotals/tax, misleading text, 3/4 pages, 20 MiB boundary, OCR load failure; confirm users can edit fields and understand all values are suggestions.
- Batch rename: 1/20/21 files, duplicate filenames, image and multi-page PDF, first-page-only behavior, ambiguous/no OCR, hostile filename characters, all files download individually, and verify source file bytes remain unchanged.
- Edit PDF: text/note/rectangle placement on first/middle/last pages, rotated pages and unusual page boxes, undo/remove item, empty/overlong text, unsupported glyphs, 500/501 items, responsive coordinate alignment, saved output rendering and text extraction.
- Page numbers: single/multi-page files, start value, each style, rotated/mixed-size pages, existing crop boxes, number width near page edges, boundary size/pages, and verify output appearance in multiple PDF readers.
- Crop: zero and asymmetric margins, non-default CropBox, mixed sizes/rotations, invalid/overlarge margins, content near each edge, and verify hidden cropped content remains as documented.
- Lock/unlock: correct password, wrong password, owner/user password distinction, 256-bit output accepted by common readers, boundary password lengths, password character handling, confirm no password is logged or retained after completion.
- Sign/watermark: page selection boundaries, long/empty signature, transparent signature strokes, page rotations/sizes, text positioning and saved visual output. Confirm UI does not call an image signature cryptographic signing.
- Metadata cleanup: seeded document information and catalog/page XMP, output properties re-opened and inspected, visible page text and layout unchanged, encrypted/damaged and boundary-size files. Confirm annotations and attachments remain as disclosed.
- Redaction: black boxes fully cover selected text/image content in the rendered result; test small/edge-aligned boxes, rotated/cropped pages, every page, encrypted/damaged files, pixel/output limits, and cancellation. Reopen the output and verify text extraction does not expose source page text and the PDF contains only the rendered page images.
- Compare PDFs: identical documents, text-only edits, scanned image-only edits, changed page dimensions, inserted/deleted pages, reordered pages, encrypted/damaged input, visual threshold, and maximum resource boundaries. Treat reported differences as review aids rather than proof of document equivalence.

### Office tools (Word, Excel, PowerPoint)

- Real fixtures from Office: styles, lists (bullets and numbering), long tables that cross pages, images, headers/footers with page numbers, landscape sections, manual page breaks.
- Spreadsheets with print areas, print titles, fit-to-page, merged cells, number/date/currency formats, wrapped text, images, charts, hidden sheets/rows/columns, CSV with commas/semicolons/quotes.
- Presentations with themes, layout backgrounds, grouped shapes, SmartArt, tables, charts, hidden slides, and speaker notes.
- Rejection cases: `.doc`/`.xls`/`.ppt`, renamed files, random bytes, empty file, password-protected OOXML, over-limit files; cancel during conversion; repeat conversion.
- Verify in at least two PDF readers that text is selectable/searchable, links work, and pages match the source visually. Compare against Office output where available.

## Capacity and accuracy statements

These tools currently perform one conversion in a user's browser; the limits are conservative guardrails, not a demonstrated concurrency or million-user capacity target. At scale, browser tools still need device/browser coverage and CDN delivery for large WASM/model assets. Office conversion also runs on the user's device, so very large or complex files depend on device memory and speed. Do not claim “handles a billion users,” complete Office format compatibility, certified PDF/A, exact OCR, or cryptographic signing without evidence and the corresponding infrastructure/certification.
