# PDF Scanner tool guide

This guide records the current implementation, its dependencies, user-facing limits, and the cases to verify before release. It is intended for engineering handoff and product discussions; it is not a claim of formal certification or million-user capacity.

## Runtime and processing model

- React 19, TypeScript, TanStack Start/Router, Vite 8, Tailwind CSS 4, Lucide React.
- `pdf-lib` edits, assembles, and saves PDFs in the browser. Dedicated Web Workers are used for image-to-PDF, page operations, PDF marks, and form flattening so those jobs do not block the UI thread.
- PDF.js (`pdfjs-dist`) parses/renders PDFs for OCR and PDF-to-JPG. It uses its own PDF worker; OCR recognition uses Tesseract.js with English language data.
- `qpdf-run` runs qpdf in WebAssembly for password encryption/decryption, structural repair, and optimization. This avoids sending these documents to a conversion server.
- Files stay in the browser for these tools. Browser memory, device capability, browser support, and worker/WASM availability therefore affect the practical maximum. A stated file limit is a guardrail, not a guarantee that every device can process a file at that limit.
- There is no server-side office conversion engine, job queue, object storage, or office font set configured in this repository. Do not describe the current client-side tools as a globally scalable backend service.

## Convert documents: current status

| Tool              | Status      | What is required for faithful output                                                                                                                                  |
| ----------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Image to PDF      | Available   | Browser image decoders and `pdf-lib`; supported formats and limits are above.                                                                                         |
| PDF to JPG        | Available   | PDF.js and browser canvas; page-at-a-time rendering and limits are above.                                                                                             |
| Word to PDF       | Coming soon | Isolated office-rendering service, preferably a pinned LibreOffice build, fonts, queue/worker capacity, temporary-file cleanup, and real DOC/DOCX fixture validation. |
| Excel to PDF      | Coming soon | Same service; validate sheets, print areas, page scaling, formulas/cached values, charts, and multi-sheet page breaks.                                                |
| PowerPoint to PDF | Coming soon | Same service; validate slide dimensions, notes policy, embedded fonts, images, charts, and transitions/animation policy.                                              |

Office formats contain layout, embedded assets, fonts, spreadsheet print settings/formulas, and presentation slide geometry. Rebuilding those from browser-parsed text would silently lose fidelity. This repository currently has no office parser or conversion engine, so the three Office tools remain visibly unavailable rather than claim to convert accurately. A server-side LibreOffice worker is a recommended next architecture, but it must be deployed and load-tested before those links are enabled. Do not forward private user documents to a third-party converter without an approved privacy and retention decision.

### Suggested Office conversion service contract

1. Browser posts one allowed file to the company-controlled conversion API over HTTPS; validate extension, MIME, magic bytes, size, and user limits server-side.
2. API creates an opaque job ID and queues conversion. Run LibreOffice in a disposable, resource-limited container with a unique profile and no network access; install the supported font set and pin the engine version.
3. Enforce per-job memory, CPU, wall-clock, page/slide/sheet, and output-size limits. Never trust client-side validation as a security boundary.
4. Return a job status and a short-lived download URL or streamed PDF. Delete source, working profile, and output after the retention window; handle cancellation and retries idempotently.
5. Add malware scanning and abuse/rate controls appropriate to the upload threat model. Publish file handling and deletion behavior to users.

## Test and release checklist

The codebase does not currently define a formal automated test script. Use this list for manual QA or turn the cases into an automated browser/worker suite. A successful TypeScript/build/lint check is not a substitute for exercising real document fixtures.

### Shared PDF cases

- Valid single- and multi-page PDFs; portrait/landscape, mixed page sizes, rotation, image-heavy pages, annotations/forms, and non-Latin content.
- Empty file, non-PDF renamed `.pdf`, truncated/corrupt xref/trailer, unsupported objects, encrypted file, and wrong password where applicable.
- Exact maximum and one-over input/output/page limits; 0-byte input; large but valid file; timeout/cancel; low-memory behavior; worker or WASM load failure; repeated runs and route unmount during processing.
- Verify the downloaded file opens in at least two independent PDF readers and visually compare representative pages. Check console for unhandled errors and ensure temporary object URLs/workers are released.

### Tool-specific cases

- Merge: 2 and 20 files, selected order, duplicate source, mixed rotations/page sizes, aggregate byte/page boundary.
- Split/extract/remove: single page, first/last page, disjoint and overlapping ranges, malformed range, out-of-range page, remove-all rejection, 20/21 ranges.
- Organize: reverse/repeated ordering attempts, rotate each direction, remove pages, preserve intended rotation in saved PDF.
- Compress/repair/archive: image optimization off/on, already-small input, warnings, malformed source, output larger than source, repairable and irrecoverable corruption. Confirm archive copy is not presented as certified PDF/A.
- OCR: clear scanned English, skew/low contrast, blank page, mixed text/image, maximum 30 pages, unsupported language expectations, offline/missing model failure; verify both text selection/search and rendered appearance.
- Flatten: form with filled and blank fields, checkbox/radio, no-fields rejection, verify flattened appearance and remaining annotations.
- Image to PDF: JPEG, transparent PNG, browser-supported WebP/AVIF, EXIF-oriented photo, corrupt and zero-byte file, GIF first frame, 100/101 files, pixel/dimension/input/output limits, ordering and all paper/margin options.
- PDF to JPG: rotated/mixed-size pages, transparent PDF graphics rendered onto white, quality slider values, single and 100-page file, per-page pixel and aggregate-pixel limits, output-size limit, password/corruption, cancel/timeout, and verify each download is a valid JPEG with expected page dimensions.
- Scan documents: front/rear/no camera, denied permission, stopped stream, rapid capture, photo import, page reorder/remove, 100/101 images, EXIF orientations, image decoder and pixel limits, worker cancellation/timeout, and open the saved PDF to verify page order and framing.
- Photo to searchable PDF: 1/30/31 photos, image order, camera/EXIF rotations, unsupported/corrupt images, generated PDF at/over OCR size limit, OCR model/network failure, cancel during assembly/OCR, and verify searchable layer visually aligns with each page.
- Smart page cleanup: all rotation angles, mixed image orientation, each enhancement, transparent PNG, unsupported browser canvas filters, boundary image dimensions/aggregate pixels, and inspect output for clipping or unreadable contrast.
- Receipt extractor: image and PDF paths, no text, skew/blur, multiple currencies/date formats, totals/subtotals/tax, misleading text, 3/4 pages, 20 MiB boundary, OCR load failure; confirm users can edit fields and understand all values are suggestions.
- Batch rename: 1/20/21 files, duplicate filenames, image and multi-page PDF, first-page-only behavior, ambiguous/no OCR, hostile filename characters, all files download individually, and verify source file bytes remain unchanged.
- Lock/unlock: correct password, wrong password, owner/user password distinction, 256-bit output accepted by common readers, boundary password lengths, password character handling, confirm no password is logged or retained after completion.
- Sign/watermark: page selection boundaries, long/empty signature, transparent signature strokes, page rotations/sizes, text positioning and saved visual output. Confirm UI does not call an image signature cryptographic signing.
- Metadata cleanup: seeded document information and catalog/page XMP, output properties re-opened and inspected, visible page text and layout unchanged, encrypted/damaged and boundary-size files. Confirm annotations and attachments remain as disclosed.
- Redaction: black boxes fully cover selected text/image content in the rendered result; test small/edge-aligned boxes, rotated/cropped pages, every page, encrypted/damaged files, pixel/output limits, and cancellation. Reopen the output and verify text extraction does not expose source page text and the PDF contains only the rendered page images.
- Compare PDFs: identical documents, text-only edits, scanned image-only edits, changed page dimensions, inserted/deleted pages, reordered pages, encrypted/damaged input, visual threshold, and maximum resource boundaries. Treat reported differences as review aids rather than proof of document equivalence.

### Before enabling Office tools

- Build a fixture set containing legacy and modern extensions (DOC/DOCX, XLS/XLSX, PPT/PPTX), embedded images/fonts, unusual page sizes, charts, formulas, multiple sheets/slides, and password-protected/corrupt files.
- Compare output rendering to approved source expectations across Linux/production fonts, not only developer Windows. Test large and hostile files in the isolated worker, concurrency/queue saturation, cancellation, worker restart, cleanup, retries, and server-side limits.
- Record supported LibreOffice version, fonts, unsupported features, data retention, and service capacity; only then mark the corresponding homepage tool available.

## Capacity and accuracy statements

These tools currently perform one conversion in a user's browser; the limits are conservative guardrails, not a demonstrated concurrency or million-user capacity target. At scale, browser tools still need device/browser coverage and CDN delivery for large WASM/model assets. Office conversion needs separately deployed and load-tested workers, queueing, quotas, monitoring, isolation, and retention controls. Do not claim “handles a billion users,” complete format compatibility, certified PDF/A, exact OCR, or cryptographic signing without evidence and the corresponding infrastructure/certification.
